认证方式

所有接口请求需在Header中携带API Key，格式如下：

HTTP Header 
Authorization: Bearer ak_your_api_key_here
请求格式规范
Content-Type
application/json
字符编码
UTF-8
时间格式
ISO 8601
如 2024-05-24T10:05:12Z
错误码总览
错误码 含义
10001认证失败（API Key无效）
10002数据格式校验失败
10003必填字段缺失
20001订单号重复
20002仓库编码不存在
20003订单状态不允许此操作
30001系统内部错误

创建订单

POST /api/v1/orders
创建新的入仓/出仓订单
Header参数
参数名类型必填说明
Authorization string 是 Bearer Token，格式：Bearer ak_xxx
Content-Type string 是 固定值：application/json
Body参数
字段名类型必填说明
sourceOrderNostring是来源订单号
customerCodestring是客户编码
warehouseCodestring是仓库编码
orderTypestring是订单类型（INBOUND/OUTBOUND）
cargoDetailsarray是货物明细
remarkstring否备注
extraDataobject否扩展字段
成功响应示例
JSON 
{
  "code": 0,
  "message": "success",
  "data": {
    "orderNo": "ORD-2024-001",
    "status": "PENDING",
    "createdAt": "2024-05-24T10:05:12Z"
  }
}
失败响应示例
JSON 
{
  "code": 10003,
  "message": "必填字段缺失: warehouseCode",
  "data": null
}

此请求将操作真实数据

响应结果

事件类型与数据结构

支持的事件类型

系统会在特定业务事件发生时，向配置的回调地址推送事件通知。以下是所有支持的事件类型：

order.created 订单创建
当新订单创建成功时触发
order.status_changed 订单状态变更
当订单状态发生变化时触发（如PENDING -> PROCESSING -> COMPLETED）
inbound.received 入仓收货确认
当仓库完成入仓收货操作时触发
outbound.shipped 出仓发货确认
当出仓订单完成发货装车时触发
inventory.warning 库存预警
当库存低于安全库存阈值时触发
事件数据结构
JSON 
{
  "eventId": "evt_a1b2c3d4e5",
  "eventType": "order.status_changed",
  "timestamp": "2024-05-24T10:30:00Z",
  "data": {
    "orderNo": "ORD-2024-001",
    "oldStatus": "PENDING",
    "newStatus": "PROCESSING"
  }
}

回调机制说明

回调流程

当业务事件发生时，系统会向开发者配置的Webhook URL发送HTTP POST请求。 开发者需要在收到请求后返回HTTP 200状态码表示接收成功。

重试机制
重试次数间隔说明
第1次立即首次推送
第2次30秒后-
第3次5分钟后-
第4次30分钟后最终重试
签名验证

每个回调请求在Header中携带签名，用于验证请求来源的真实性：

HTTP Header 
X-SDMS-Signature: sha256=hmac_sha256(webhook_secret, request_body)
